Projects도 아직 만든 것으로 간주하지 않습니다. 4명 팀은 `할 일 / 진행 중 / 검토 중 / 완료`로 시작하고 #3, #6, #7, 선택 과제 #8을 넣으면 됩니다. 레이블은 기존 `bug`, `enhancement`, `documentation`, `good first issue`를 재사용합니다. 한국어·난이도 레이블 추가는 선택입니다.

## 통합 제안과 승인 범위

`main`과 배포 브랜치는 README 변경 때문에 갈라져 있습니다. 이번 `review/oss-dec02-readiness`는 기존 배포 코드와 main의 접속 링크를 모두 보존하는 **통합 검토안**입니다. 기존 커밋을 새 최초 버전으로 복사하지 않고 두 이력을 부모로 보존합니다.

- main에는 아직 병합하지 않습니다. 공개 사이트도 재배포하지 않습니다.
- 새 통합 PR을 검토하는 방식을 택하면 기존 #2·#4·#5는 이력으로 남깁니다. 통합 승인 후 각 PR을 실제 포함 여부에 맞게 정리합니다. 현재는 닫지 않습니다.
- 기존 단계별 PR을 순서대로 처리하고 싶다면 통합 PR은 사용하지 않고 기준 브랜치를 다시 합의합니다. 두 경로를 중복으로 병합하지 않습니다.
- 자동 테스트가 통과해도 교수님 기준 충족이나 팀원의 실제 리뷰를 대신하지 않습니다.

## 반드시 구분할 것

1. 영구 저장이 없는 상태에서 로그인만 넣어도 기록은 사라질 수 있습니다. #6에서 저장 방식부터 정합니다.
2. 시간 진행과 결과 분석은 이미 구현되어 있습니다. 재개발보다 사용자가 발견하도록 안내하고 테스트합니다.
3. 주말을 전체 시작 달력에서 막으면 코인 거래까지 제한됩니다. 종목별 거래일 안내가 더 적절합니다.
4. 수수료/세금, 시장 지수 비교, 실제 시세 공급자 교체(#8)는 남은 시간과 기준을 보고 선택합니다. 미국 주식·코인과 코스피를 무조건 같은 기준으로 비교하지 않습니다.
5. 팀원별 최소 PR 수나 커밋 수를 교수님이 요구했다고 단정하지 않습니다. 의미 있는 실제 변경과 검증을 남깁니다.
